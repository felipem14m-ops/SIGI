# Registrar Movimiento de Inventario

La lógica de esta funcionalidad se maneja principalmente desde la vista auth/Admininventario.php.

Para realizar esta acción, el usuario interactúa con el botón "Registrar Movimiento" que abre un modal con el formulario. El javascript de la página se encarga de mostrar el modal con los campos necesarios: un select para elegir el producto donde se puede buscar por nombre o código, un select para elegir el tipo de movimiento que puede ser entrada de mercancía, ajuste positivo, devolución de cliente para sumar stock, o ajuste negativo y merma para restar stock, un campo numérico para ingresar la cantidad del movimiento que debe ser mayor a cero, y un campo de texto para el motivo que explica por qué se realiza el movimiento.

Al momento de enviar los datos, el formulario en su atributo action está conectado directamente con el archivo InventarioController.php con el parámetro accion=registrar. Dentro de este controlador, el sistema pasa por la acción o función llamada registrar en función principal.

Cabe recordar que este controlador incluye todos los archivos de configuración como database.php para tener permisos en la base de datos, y se apoya en el modelo Inventario.php necesario para interactuar con las tablas productos y movimiento_inventario. Una vez que el controlador valida los datos recibidos del formulario, verifica que se haya seleccionado un producto, que se haya seleccionado un tipo de movimiento, que la cantidad sea un número entero mayor a cero, y que se haya proporcionado un motivo. También obtiene el ID del usuario desde la sesión para registrar quién realizó el movimiento. Después de todas estas validaciones, el controlador llama al método registrarMovimiento del modelo pasándole el ID del producto, ID del usuario, ID del tipo de movimiento, cantidad y motivo.

El modelo Inventario.php recibe los datos y ejecuta todo el proceso dentro de una transacción de base de datos para garantizar consistencia. Primero inicia la transacción con beginTransaction. Luego consulta el tipo de movimiento en la tabla tipos_movimiento para saber si el signo es más o menos, es decir si suma o resta stock. También consulta el producto para obtener su stock actual. Calcula el nuevo stock sumando o restando la cantidad según el signo del tipo de movimiento. Si el nuevo stock resultaría negativo, lanza una excepción indicando que no hay suficiente stock para realizar ese movimiento. Si el nuevo stock es válido, inserta un registro en la tabla movimiento_inventario con el ID del producto, ID del usuario, ID del tipo de movimiento, cantidad, stock anterior, stock resultante, origen marcado como manual para diferenciarlo de los movimientos automáticos por ventas, motivo proporcionado por el usuario, y fecha actual. Luego actualiza el campo stock_actual del producto con el nuevo valor calculado. Si todo se ejecuta sin errores, hace commit de la transacción y retorna true. Si ocurre cualquier error, hace rollback para deshacer todos los cambios y retorna el mensaje de error.

Al finalizar el proceso con éxito o si ocurre algún error, el mismo controlador se encarga de hacer el redireccionamiento para devolver al usuario a la vista auth/Admininventario.php, mostrando un mensaje flotante con SweetAlert2 indicando si el movimiento fue registrado correctamente o si hubo algún error en el proceso. El nuevo movimiento aparece inmediatamente en el kardex del producto y el stock actualizado se refleja en todas las vistas del sistema.
