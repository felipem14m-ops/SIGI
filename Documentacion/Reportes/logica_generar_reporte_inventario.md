# Generar Reporte de Inventario

La lógica de esta funcionalidad se maneja principalmente desde la vista auth/Adminreportes.php.

Para realizar esta acción, el usuario interactúa con tarjetas visuales que representan diferentes tipos de reportes disponibles: Inventario Actual que genera un PDF con todos los productos activos, Filtros Avanzados que abre un modal para personalizar el reporte por categoría estado o fechas, y Alertas de Stock que genera un PDF solo con productos que tienen stock crítico. El javascript de la página se encarga de capturar la acción del usuario y ejecutar la función correspondiente.

Cuando el usuario hace clic en "GENERAR REPORTE PDF" de cualquiera de las tarjetas, el javascript muestra un mensaje de carga con SweetAlert2 indicando que está procesando. Luego ejecuta una petición fetch al archivo ReporteController.php con el parámetro accion=obtener_datos_inventario. Si es un reporte con filtros, envía los parámetros adicionales mediante POST con FormData incluyendo id_categoria, estado, fecha_desde, fecha_hasta o stock_bajo según lo que el usuario haya seleccionado en el modal de filtros.

Cabe recordar que este controlador incluye todos los archivos de configuración como database.php para tener permisos en la base de datos, y se apoya en el modelo Reporte.php necesario para interactuar con la tabla productos y sus relaciones. El controlador recibe la petición, construye un array de filtros con los parámetros recibidos estableciendo null para los filtros no aplicados y true para stock_bajo si viene ese parámetro. Luego llama al método obtenerInventarioFiltrado del modelo pasándole el array de filtros.

El modelo Reporte.php ejecuta una consulta SQL de tipo SELECT con LEFT JOIN para traer los productos junto con el nombre de su categoría y el nombre de su proveedor. La consulta base trae todos los campos necesarios para el reporte: código único, nombre, categoría, proveedor, precios de costo y venta, stock actual, stock mínimo, estado y fecha de creación. Luego la consulta agrega condiciones WHERE dinámicamente según los filtros recibidos. Si hay filtro de categoría agrega AND id_categoria igual al valor. Si hay filtro de estado agrega AND estado igual al valor. Si hay filtro de fecha desde agrega AND fechaCreacion mayor o igual a la fecha. Si hay filtro de fecha hasta agrega AND fechaCreacion menor o igual a la fecha con hora 23:59:59. Si hay filtro de stock bajo agrega AND stock_actual menor o igual a stock_minimo. Los resultados se ordenan alfabéticamente por nombre de producto. El modelo retorna un array con todos los productos que cumplen los filtros o un array vacío si no hay resultados.

El controlador recibe el array de productos del modelo y construye un objeto JSON con estructura ok true, data con el array de productos, filtros aplicados, fecha y hora actual, y nombre del usuario que genera el reporte obtenido de la sesión. Este JSON se envía como respuesta al javascript con header Content-Type application/json y charset utf-8 para asegurar que los caracteres especiales se muestren correctamente.

El javascript recibe el JSON, verifica que ok sea true y que data contenga productos. Si no hay productos muestra un mensaje indicando que el inventario está vacío o que no se encontraron resultados con esos filtros. Si hay productos, el javascript crea una instancia de la clase SIGIPDFGenerator que está definida en el archivo JS/PDFGenerator.js. Esta clase utiliza las librerías jsPDF y jsPDF-AutoTable que se cargan desde CDN para generar PDFs profesionales en el navegador sin necesidad de procesamiento en el servidor.

La clase SIGIPDFGenerator recibe el título del reporte como parámetro en el constructor. Luego el javascript llama al método generateTable pasándole un array de encabezados de columnas y un array de datos procesados. El procesamiento de datos convierte cada producto en un array con los valores en el orden correcto: código, nombre, categoría, precio de costo formateado con símbolo de peso y separadores de miles, precio de venta formateado igual, stock actual, stock mínimo y estado en mayúsculas. La clase genera automáticamente el encabezado del PDF con fondo azul institucional, el logo del sistema si existe, el título del reporte, la fecha y hora de generación. Luego genera la tabla con los datos usando AutoTable que maneja automáticamente el paginado si los datos no caben en una página, aplica estilos profesionales con colores institucionales, alterna colores de filas para mejor legibilidad, y agrega el pie de página con número de página en cada hoja. Finalmente descarga el PDF automáticamente en el navegador con un nombre único que incluye el título del reporte y un timestamp.

Para el reporte de stock bajo, el javascript puede aplicar estilos especiales a la tabla configurando que todas las celdas del cuerpo tengan color de texto rojo para resaltar la criticidad de la situación. El usuario recibe el PDF descargado y puede abrirlo, imprimirlo o compartirlo según necesite. Todo el proceso ocurre en el navegador del cliente lo que hace que sea muy rápido y no sobrecarga el servidor.
