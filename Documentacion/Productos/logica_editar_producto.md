# Editar Producto

La lógica de esta funcionalidad se maneja principalmente desde la vista auth/Adminproductos.php.

Para realizar esta acción, el usuario interactúa con el botón de editar que se encuentra en cada fila de la tabla de productos. El javascript de la página se encarga de capturar el ID del producto seleccionado, buscar sus datos en el array de productos que está cargado en formato JSON, y prellenar todos los campos del modal de edición con la información actual del producto incluyendo código, nombre, descripción, categoría, proveedor, precios, stock mínimo, fecha de vencimiento, estado y si tiene imagen muestra una vista previa de la misma.

Al momento de enviar los datos modificados, el formulario en su atributo action está conectado directamente con el archivo ProductoController.php con el parámetro accion=editar. El formulario incluye un campo oculto con el ID del producto y otro campo oculto con el nombre de la imagen actual. Dentro de este controlador, el sistema pasa por la acción o función llamada editar en función principal.

Cabe recordar que este controlador incluye todos los archivos de configuración como database.php para tener permisos en la base de datos, y se apoya en el modelo Producto.php necesario para interactuar con la tabla productos. Una vez que el controlador recibe los datos, primero valida que el ID del producto sea un número entero válido mayor a cero. Luego valida que el código único no esté vacío, que el nombre no esté vacío y que se haya seleccionado una categoría. Si el usuario subió una nueva imagen, el controlador valida el formato y tamaño, genera un nombre único, elimina la imagen anterior del servidor si existía, y mueve la nueva imagen a la carpeta IMG/productos. Si no se subió nueva imagen, mantiene el nombre de la imagen actual que viene del campo oculto. Después de todas estas validaciones, el controlador llama al método actualizar del modelo pasándole el ID y todos los datos modificados.

El modelo Producto.php recibe el ID y los datos, y antes de actualizar verifica en la base de datos si el código único ya existe en otro producto excluyendo el producto actual de la búsqueda. Si el código está duplicado en otro producto, retorna un mensaje de error. Si el código es válido, el modelo prepara una consulta SQL de tipo UPDATE con todos los campos usando consultas preparadas con PDO. La consulta actualiza el producto en la tabla productos modificando código único, nombre, descripción, categoría, proveedor, precios, stock mínimo, fecha de vencimiento, estado e imagen. Es importante mencionar que el stock actual NO se modifica desde este módulo, solo se gestiona desde el módulo de Inventario para mantener el control del kardex.

Al finalizar el proceso con éxito o si ocurre algún error, el mismo controlador se encarga de hacer el redireccionamiento para devolver al usuario a la vista auth/Adminproductos.php, mostrando un mensaje flotante con SweetAlert2 indicando si el producto fue actualizado correctamente o si hubo algún error en el proceso.
