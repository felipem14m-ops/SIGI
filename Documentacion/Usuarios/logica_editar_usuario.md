# Editar Usuario

La lógica de esta funcionalidad se maneja principalmente desde la vista auth/Adminusuarios.php.

Para realizar esta acción, el usuario administrador interactúa con el botón de editar que se encuentra en cada fila de la tabla de usuarios. El javascript de la página se encarga de capturar el ID del usuario seleccionado, buscar sus datos en el array de usuarios que está cargado en formato JSON, y prellenar todos los campos del modal de edición con la información actual del usuario incluyendo nombre, número de identificación, email y rol. Por seguridad, la contraseña no se muestra ni se prellena.

Al momento de enviar los datos modificados, el formulario en su atributo action está conectado directamente con el archivo AdmiUsuarioController.php con el parámetro accion=editar. El formulario incluye un campo oculto con el ID del usuario. Dentro de este controlador, el sistema pasa por la acción o función llamada editar en función principal.

Cabe recordar que este controlador incluye todos los archivos de configuración como database.php para tener permisos en la base de datos, y se apoya en el modelo Usuario.php necesario para interactuar con la tabla usuarios. Una vez que el controlador recibe los datos, primero valida que el ID del usuario sea un número entero válido mayor a cero. Luego valida que el nombre no esté vacío, que el número de identificación no esté vacío, que el email no esté vacío y tenga formato válido, y que el rol sea válido. El controlador verifica que el número de identificación y el email no estén ya registrados en otro usuario excluyendo el usuario actual de la búsqueda. Si se proporcionó una nueva contraseña en los campos opcionales de contraseña y confirmación, el controlador valida que cumplan requisitos mínimos, que coincidan entre sí, y hashea la nueva contraseña. Si no se proporcionó nueva contraseña, se mantiene la contraseña actual. Después de todas estas validaciones, el controlador llama al método actualizar del modelo pasándole el ID y todos los datos modificados.

El modelo Usuario.php recibe el ID y los datos, y prepara una consulta SQL de tipo UPDATE. Si se proporcionó nueva contraseña, la consulta actualiza los campos nombre, numeroIdentificacion, email, contrasena hasheada y id_rol. Si no se proporcionó nueva contraseña, la consulta actualiza solo nombre, numeroIdentificacion, email y id_rol dejando la contraseña sin cambios. La consulta usa consultas preparadas con PDO. Si el número de identificación o email modificados ya existen en otro usuario, MySQL retorna error por los constraints UNIQUE y el modelo lo captura.

Al finalizar el proceso con éxito o si ocurre algún error, el mismo controlador se encarga de hacer el redireccionamiento para devolver al usuario a la vista auth/Adminusuarios.php, mostrando un mensaje flotante con SweetAlert2 indicando si el usuario fue actualizado correctamente o si hubo algún error en el proceso. Si se cambió el rol del usuario, los cambios en permisos se aplican en su próximo inicio de sesión. Si se cambió la contraseña, el usuario deberá usar la nueva contraseña en su próximo login.
