# Registrar Usuario

La lógica de esta funcionalidad se maneja principalmente desde la vista auth/Adminusuarios.php.

Para realizar esta acción, el usuario administrador interactúa con el botón "Nuevo Usuario" que abre un modal con el formulario. El javascript de la página se encarga de mostrar el modal con los campos necesarios: nombre completo del usuario que es obligatorio, número de identificación único que puede ser cédula o documento de identidad, email único que se usará para login y comunicaciones, contraseña que debe cumplir requisitos mínimos de seguridad, confirmación de contraseña para evitar errores de digitación, y un select para elegir el rol que puede ser Administrador con acceso completo o Empleado con acceso limitado solo a ventas y consultas.

Al momento de enviar los datos, el formulario en su atributo action está conectado directamente con el archivo AdmiUsuarioController.php con el parámetro accion=crear. Dentro de este controlador, el sistema pasa por la acción o función llamada crear en función principal.

Cabe recordar que este controlador incluye todos los archivos de configuración como database.php para tener permisos en la base de datos, y se apoya en el modelo Usuario.php necesario para interactuar con la tabla usuarios. Una vez que el controlador valida los datos recibidos del formulario, verifica que el nombre no esté vacío, que el número de identificación no esté vacío, que el email no esté vacío y tenga formato válido, que la contraseña no esté vacía y cumpla requisitos mínimos como longitud mínima de 8 caracteres, que la confirmación de contraseña coincida con la contraseña, y que se haya seleccionado un rol válido. El controlador también verifica que el número de identificación y el email no estén ya registrados en el sistema llamando a métodos del modelo. Si todas las validaciones pasan, el controlador hashea la contraseña usando password_hash con el algoritmo bcrypt para almacenarla de forma segura, y luego llama al método crear del modelo pasándole todos los datos saneados.

El modelo Usuario.php recibe los datos y prepara una consulta SQL de tipo INSERT con los campos id_rol, nombre, numeroIdentificacion, email, contrasena hasheada, activo establecido en 1 por defecto, intentos_fallidos en 0, bloqueado_hasta en NULL, y fecha_creacion que se llena automáticamente. La consulta usa consultas preparadas con PDO para prevenir inyección SQL. Si el número de identificación o el email ya existen, MySQL retorna un error por los constraints UNIQUE y el modelo lo captura para retornar un mensaje apropiado indicando qué campo está duplicado.

Al finalizar el proceso con éxito o si ocurre algún error, el mismo controlador se encarga de hacer el redireccionamiento para devolver al usuario a la vista auth/Adminusuarios.php, mostrando un mensaje flotante con SweetAlert2 indicando si el usuario fue registrado correctamente o si hubo algún error en el proceso. El nuevo usuario puede iniciar sesión inmediatamente con su email y contraseña, y tendrá acceso según el rol asignado.
