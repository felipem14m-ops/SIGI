# Procesar Venta

La lógica de esta funcionalidad se maneja principalmente desde la vista auth/ventas.php para empleados o auth/Adminventas.php para administradores.

Para realizar esta acción, el usuario interactúa con un sistema POS completo que muestra en la columna izquierda todos los productos activos disponibles con sus imágenes, nombres, precios y stock actual, y en la columna derecha un carrito de compras donde se van agregando los productos seleccionados. El javascript de la página se encarga de toda la lógica del carrito: agregar productos, modificar cantidades, calcular subtotales y total, validar stock disponible y gestionar el método de pago.

Cuando el usuario hace clic en un producto, el javascript ejecuta la función agregarAlCarrito que verifica si el producto ya está en el carrito. Si ya está, incrementa la cantidad validando que no supere el stock disponible. Si no está, lo agrega con cantidad 1 siempre que haya stock disponible. El carrito se actualiza en tiempo real mostrando cada producto con su nombre, precio unitario, cantidad, subtotal y botones para aumentar, disminuir o eliminar. En la parte inferior del carrito se muestra el total a pagar en grande y destacado, un select para elegir el método de pago entre efectivo, tarjetas, transferencia, Nequi o Daviplata, y si se selecciona efectivo aparece un campo adicional para ingresar el monto recibido que calcula automáticamente el cambio a devolver.

Al momento de hacer clic en el botón "PROCESAR VENTA", el javascript valida que el carrito no esté vacío, que se haya seleccionado un método de pago, y si es efectivo que el monto recibido sea mayor o igual al total. Si todas las validaciones pasan, el javascript construye un objeto JSON con toda la información de la venta: ID del método de pago, total, monto recibido opcional, cambio devuelto opcional, y un array de productos donde cada producto incluye su ID, cantidad y precio. Este objeto JSON se envía mediante fetch con método POST al archivo VentaController.php con el parámetro accion=crear.

Cabe recordar que este controlador incluye todos los archivos de configuración como database.php para tener permisos en la base de datos, y se apoya en el modelo Venta.php necesario para interactuar con las tablas venta, detalleventa, productos y movimiento_inventario. El controlador recibe el JSON, lo decodifica y valida que contenga productos y método de pago. También obtiene el ID del usuario desde la sesión para registrar quién realizó la venta. Una vez validado todo, el controlador llama al método procesarVenta del modelo pasándole los datos de la venta y el array de productos.

El modelo Venta.php ejecuta todo el proceso dentro de una transacción de base de datos para garantizar que todo se ejecute correctamente o nada se ejecute en caso de error. Primero inicia la transacción con beginTransaction. Luego inserta un registro en la tabla venta con el ID del usuario, ID del método de pago, total, monto recibido, cambio devuelto y estado completada, y obtiene el ID de la venta recién insertada. Después, para cada producto en el array, el modelo ejecuta un SELECT con FOR UPDATE para bloquear el registro del producto y leer su stock actual de forma segura. Si el stock es insuficiente, lanza una excepción con el nombre del producto. Si hay stock suficiente, inserta un registro en la tabla detalleventa con el ID de la venta, ID del producto, cantidad, precio unitario y subtotal. Luego actualiza el stock del producto restando la cantidad vendida. Finalmente inserta un registro en la tabla movimiento_inventario con tipo de movimiento 2 que es salida por venta, marcado como origen automático, registrando el stock anterior, el stock resultante y un motivo que indica el número de venta. Si todo se ejecuta sin errores, hace commit de la transacción y retorna el ID de la venta. Si ocurre cualquier error, hace rollback para deshacer todos los cambios y retorna el mensaje de error.

Al finalizar el proceso, el controlador retorna un JSON al javascript indicando si fue exitoso con el ID de la venta o si hubo error con el mensaje. El javascript muestra un mensaje con SweetAlert2 indicando el resultado, y si fue exitoso limpia el carrito, resetea el formulario y deja el sistema listo para la siguiente venta. Si hubo error, muestra el mensaje específico para que el usuario pueda corregir el problema.
