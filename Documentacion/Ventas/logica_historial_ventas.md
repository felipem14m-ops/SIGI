# Historial de Ventas

La lógica de esta funcionalidad se maneja principalmente desde la vista auth/Adminhistorialventas.php.

Para realizar esta acción, el usuario accede al módulo de historial de ventas desde el menú lateral del sistema. Esta vista está restringida únicamente para usuarios con rol de Administrador, por lo que si un empleado intenta acceder directamente mediante la URL, el sistema lo redirige automáticamente a su dashboard correspondiente. Al momento de cargar la página, la vista ejecuta consultas al modelo Venta.php llamando al método listarVentas que trae todas las ventas registradas en el sistema con su información completa.

El modelo Venta.php ejecuta una consulta SQL de tipo SELECT con múltiples JOIN para traer las ventas junto con información relacionada de otras tablas. La consulta principal une la tabla venta con la tabla usuarios para obtener el nombre del cajero que procesó la venta, y con la tabla metodos_pago para obtener el nombre del método de pago utilizado. Además, la consulta incluye una subconsulta que suma las cantidades de la tabla detalleventa para calcular el total de ítems vendidos en cada transacción. Los resultados se ordenan por fecha de venta de forma descendente para mostrar las ventas más recientes primero.

La vista proporciona un sistema de filtros avanzado que permite al administrador buscar ventas específicas. El primer filtro es por fecha de venta, donde el usuario puede seleccionar una fecha específica usando un campo de tipo date que muestra un calendario visual. El segundo filtro es por nombre de usuario o cajero, donde se puede escribir el nombre completo o parcial del empleado que realizó la venta. Estos filtros se envían mediante el método GET al recargar la página, y el modelo los recibe como parámetros opcionales en el método listarVentas.

Cuando se aplican filtros, el modelo construye dinámicamente las condiciones WHERE de la consulta SQL. Si se proporciona un filtro de fecha, agrega una condición que compara la fecha de la venta usando la función DATE para extraer solo la parte de fecha sin la hora. Si se proporciona un filtro de usuario, agrega una condición con LIKE para buscar coincidencias parciales en el nombre del cajero, permitiendo búsquedas flexibles sin necesidad de escribir el nombre completo. Los parámetros se vinculan de forma segura usando bindValue para prevenir inyección SQL. Si no se aplican filtros, la consulta trae todas las ventas del sistema sin restricciones.

Una vez que los datos llegan a la vista, se renderizan en una tabla HTML estilizada con diseño premium que muestra columnas para folio de venta con formato de cinco dígitos con ceros a la izquierda, fecha y hora en formato legible día mes año hora minutos AM PM, nombre del usuario o cajero con un ícono de avatar circular, método de pago en un badge con ícono de tarjeta, total de ítems en un badge azul redondeado, total de la venta en formato de moneda con separadores de miles, cambio devuelto en color verde si es mayor a cero o gris si es cero, y un botón de acciones para ver el detalle completo.

La tabla utiliza la librería DataTables de JavaScript que se inicializa automáticamente al cargar la página con configuración personalizada. DataTables está configurado para mostrar 20 registros por página, ordenar por defecto por la columna de fecha en orden descendente para mostrar las ventas más recientes primero, y deshabilitar el ordenamiento en la columna de acciones. La configuración del DOM está personalizada para mostrar solo la tabla y la paginación en la parte inferior con información del total de registros. El idioma está configurado en español con textos personalizados para los botones de paginación y mensajes informativos.

Desde esta tabla el usuario puede realizar la acción de ver detalle completo de cualquier venta. Al hacer clic en el botón de ojo, se ejecuta una función JavaScript llamada verDetalle que recibe el ID de la venta como parámetro. Esta función primero construye dinámicamente un modal flotante con overlay oscuro y efecto de desenfoque en el fondo. El modal tiene un diseño premium con bordes redondeados, sombras suaves y animación de entrada. Mientras se carga la información, el modal muestra un spinner de carga centrado.

La función verDetalle realiza una petición asíncrona con fetch al controlador VentaController.php con el parámetro accion=detalle y el ID de la venta. El controlador valida que el ID sea un número entero válido usando filter_input con FILTER_VALIDATE_INT. Si el ID no es válido, retorna un error en formato JSON. Si el ID es válido, el controlador llama a dos métodos del modelo: obtenerCabeceraVenta que trae los datos principales de la venta incluyendo totales, método de pago, cajero y fechas, y obtenerDetalleVenta que trae todos los productos vendidos con sus cantidades, precios unitarios y subtotales.

El método obtenerCabeceraVenta ejecuta una consulta SQL con JOIN a las tablas usuarios y metodos_pago para traer el nombre del cajero y el nombre del método de pago. La consulta usa LIMIT 1 porque solo debe existir una venta con ese ID. Si no encuentra la venta, retorna false. El método obtenerDetalleVenta ejecuta una consulta SQL con JOIN a la tabla productos para traer el nombre del producto y su código único junto con los datos de cantidad, precio unitario y subtotal de la tabla detalleventa. Si no hay productos, retorna un array vacío.

Cuando la respuesta JSON llega al cliente, la función JavaScript verifica si la propiedad ok es true. Si es true, construye dinámicamente el HTML del detalle de la venta con un formato de ticket de compra. El ticket muestra en la parte superior el nombre de la tienda SIGI, el NIT y el número de folio de la venta. En la sección central muestra una lista de todos los productos vendidos con su nombre en negrita, cantidad por precio unitario en texto pequeño y gris, y el subtotal alineado a la derecha. En la parte inferior muestra el total en grande y negrita, y si la venta fue en efectivo, muestra también el monto recibido y el cambio devuelto en color verde.

El modal incluye dos botones en el pie: un botón de cerrar que ejecuta la función cerrarModalHst para remover el modal y el overlay del DOM, y un botón de imprimir con ícono de impresora que ejecuta window.print para abrir el diálogo de impresión del navegador. Al imprimir, el navegador captura el contenido visible del modal y lo formatea para impresión, permitiendo generar un comprobante físico de la venta si es necesario.

Es importante mencionar que el historial de ventas no permite editar ni eliminar ventas ya registradas, esto es una medida de auditoría y control financiero. Una vez que una venta se procesa y se registra en la base de datos, queda como registro permanente para fines contables y de trazabilidad. Si se detecta un error en una venta, la práctica recomendada es registrar una nota de crédito o devolución en lugar de modificar el registro original.

La vista también incluye un banner premium en la parte superior que muestra estadísticas rápidas como el total de registros cargados en la tabla actual. Este contador se actualiza dinámicamente según los filtros aplicados, mostrando solo la cantidad de ventas que cumplen con los criterios de búsqueda. El banner también incluye un botón de acceso rápido para crear una nueva venta que redirige a la vista Adminventas.php.

Para catálogos muy grandes con miles de ventas, el rendimiento se mantiene óptimo gracias a la paginación del lado del cliente que maneja DataTables. Sin embargo, si el sistema crece a decenas de miles de ventas, se podría considerar implementar paginación del lado del servidor donde solo se cargan los registros de la página actual, reduciendo el tiempo de carga inicial y el consumo de memoria del navegador.
